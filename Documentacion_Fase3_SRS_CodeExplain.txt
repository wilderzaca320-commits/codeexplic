==============================================================================
 1. INTRODUCCION
==============================================================================

1.1 PROPOSITO
Este SRS define de forma verificable que debe hacer CodeExplain y bajo que
condiciones se acepta. Es el contrato entre el dueno del producto, el
desarrollador y los usuarios que consumen las explicaciones y la documentacion
generada. Es la entrada de la Fase 4 (diseno detallado) y del plan de pruebas.

1.2 ALCANCE
Dentro del alcance (v1.0):
  - Analisis de un proyecto cargado como ZIP, URL Git o codigo pegado.
  - Explicacion en 3 niveles (basico, intermedio, avanzado) con IA o fallback.
  - 12 vistas de analisis: vision general, arquitectura y modulos, C4/UML,
    modelo de datos, casos de uso, riesgos, deuda tecnica, repositorios,
    historial, generador de documentacion, chat y proyectos.
  - Generacion y descarga de documentacion (README, OpenAPI, C4, ADR).

Fuera del alcance (v1.0) -> seccion 3.7:
  - Autenticacion multiusuario, facturacion, colaboracion en tiempo real,
    app movil, ejecucion del codigo analizado y marketplace de plugins.

1.3 DEFINICIONES Y ACRONIMOS
+----------------+-----------------------------------------------------------+
| Termino        | Significado                                               |
+----------------+-----------------------------------------------------------+
| AST            | Arbol de sintaxis abstracta; base del analisis estatico.  |
| Digest         | Inventario + muestra de texto del proyecto (no el ZIP).   |
| SLOC           | Lineas de codigo fuente sin blancos ni comentarios.       |
| SPOF           | Single Point of Failure (punto unico de falla).           |
| C4             | Modelo de diagramas Contexto / Contenedores / Componentes.|
| ADR            | Architecture Decision Record.                             |
| CVE            | Identificador publico de vulnerabilidad.                  |
| STRIDE         | Modelo de amenazas (Spoofing, Tampering, Repudiation...). |
| RF / RNF       | Requerimiento funcional / no funcional.                   |
| RN / RE        | Regla de negocio / restriccion.                           |
| MoSCoW         | Must, Should, Could, Won't.                               |
| Fallback       | Motor heuristico local que responde si Gemini no esta.    |
| CA             | Criterio de aceptacion.                                   |
| CU             | Caso de uso.                                              |
| TC             | Test case (prueba).                                       |

==============================================================================
 2. DESCRIPCION GENERAL
==============================================================================

2.1 PERSPECTIVA DEL PRODUCTO
CodeExplain es una SPA (React 19 + TypeScript + Vite) servida por un backend
Express que expone la IA (Google Gemini 2.5 Flash) y un motor de respaldo. El
navegador extrae y resume el proyecto; el servidor interpreta ese resumen y
devuelve analisis, respuestas y documentos.

  +------------------+      HTTPS/JSON      +---------------------------+
  | Navegador (SPA)  | -------------------> | Express (server.ts)       |
  | 12 vistas        |                      |  /api/gemini/chat         |
  | JSZip (extrae)   | <------------------- |  /api/gemini/explain      |
  | Estado en memoria|        JSON          |  /api/gemini/document     |
  +------------------+                      |  /api/analyze       [P]   |
         |                                  |  /api/analyze-url   [P]   |
         | lee el ZIP                       +-------------+-------------+
         v                                                |
  +------------------+                                    v
  | Archivo .zip     |                      +---------------------------+
  | del usuario      |                      | Gemini API (si hay key)   |
  +------------------+                      | o motor heuristico local  |
                                            +---------------------------+

2.2 FUNCIONES PRINCIPALES (15 modulos)
+------+----------------------------+-----------------------------------------+
| Mod  | Nombre                     | Funcion principal                       |
+------+----------------------------+-----------------------------------------+
| M1   | Navegacion / Shell         | 12 vistas, selector de proyecto/nivel.  |
| M2   | Proyectos                  | Alta, seleccion y tarjetas de proyecto. |
| M3   | Ingesta de repositorios    | ZIP, URL Git o codigo pegado + analisis.|
| M4   | Chat IA                    | Explicacion en 3 niveles con contexto.  |
| M5   | Vision General             | Dashboard de metricas y accesos.        |
| M6   | Arquitectura & Modulos     | Acoplamiento Ca/Ce/I por modulo.        |
| M7   | Diagramas C4 & UML         | Diagrama interactivo y detalle de nodo. |
| M8   | Modelo de Datos / BD       | Tablas, PK/FK/unique y particion.       |
| M9   | Casos de Uso               | Actor, pre/postcondicion y Gherkin.     |
| M10  | Riesgos & Validacion       | Riesgos STRIDE y CVE.                   |
| M11  | Auditor de Deuda Tecnica   | Horas de deuda y dependencias obsoletas.|
| M12  | Generador de Documentacion | README, OpenAPI, C4 y ADR descargables. |

| M15  | Configuracion / IA / Seg.  | API key, limites, fallback y errores.   |
+------+----------------------------+-----------------------------------------+

2.3 CLASES DE USUARIOS
+----------------------+----------------------------------------------------+
| Clase                | Necesidad principal                                |
+----------------------+----------------------------------------------------+
| U1 Desarrollador     | Entender codigo ajeno y documentarlo rapido.       |
| U2 Estudiante        | Explicaciones basicas con analogias.               |
| U3 Arquitecto/Revisor| Metricas de acoplamiento, riesgos y C4.            |
| U4 Docente/Evaluador | Verificar que la explicacion sea correcta.         |
| U5 Dueno del producto| Ver el estado real del sistema y su adopcion.      |
| U6 Administrador TI  | Configurar la API key, el puerto y los limites.    |
+----------------------+----------------------------------------------------+
Actores externos: Gemini API (proveedor de IA), hosting Git (GitHub, GitLab,
Bitbucket) y el navegador del usuario.

2.4 ENTORNO OPERATIVO
  - Servidor: Node.js 20+, Express 4, ejecucion con `npm run dev` (tsx).
  - Cliente: navegadores modernos con ES2022 (Chrome/Edge 110+, Firefox 110+).
  - Sistema verificado: Windows 11; ruta del proyecto sin caracteres especiales.
  - Puerto: variable PORT (valor usado en este equipo: 3100; 3000 reservado).
  - Persistencia: en memoria (v1.0); no requiere base de datos para arrancar.

2.5 RESTRICCIONES (detalle en 3.4)
  RE-01 Node.js 20+ y navegador ES2022.
  RE-02 Puerto configurable por PORT (3100 en este equipo).
  RE-03 Ruta sin "a con tilde" ni "&" por compatibilidad de npm en Windows.
  RE-04 La API key solo se lee del entorno del servidor.
  RE-05 El analisis no ejecuta el codigo del proyecto cargado.

2.6 SUPUESTOS Y DEPENDENCIAS
  S1. Existe GEMINI_API_KEY valida para el modo IA real; sin ella se usa fallback.
  S2. Hay conexion a internet para el modo IA y para la ingesta por URL Git.
  S3. El usuario tiene permiso para subir el codigo que analiza.
  S4. El ZIP no supera 200 MB y contiene archivos legibles.
  S5. La cuota de Gemini alcanza para la sesion de uso prevista.

2.7 REQUISITOS DE ALTO NIVEL (resumen)
  HN-01 Cargar un proyecto y obtener un analisis en menos de 2 minutos.
  HN-02 Explicar cualquier modulo en 3 niveles de audiencia.
  HN-03 Generar documentacion util y descargable del proyecto activo.
  HN-04 No interrumpir la sesion si la IA falla (fallback obligatorio).
  HN-05 No exponer credenciales ni datos sensibles al navegador.

3.1 CONVENCIONES
  Formato de cada RF:

--- M1. NAVEGACION / SHELL --------------------------------------------------

RF-FE-01 | M1 Navegacion | Sidebar de 12 vistas | FE | RF | U | MoSCoW: M
  Descripcion: Muestra las 12 vistas agrupadas en 3 bloques (Explorar,
    Analisis, Herramientas IA).
  Entradas   : Sesion activa; lista de vistas definida en App.tsx/Sidebar.tsx.
  Proceso    : Renderiza los grupos y marca la vista actual.
  Salidas    : Menu lateral con 12 items navegables.
  CA-01: Dado un usuario en la app, cuando observa el sidebar, entonces ve 12
         items distribuidos en 3 grupos con titulo.
  CA-02: Dado que hace clic en un item, entonces la vista cambia sin recargar.

RF-FE-02 | M1 Navegacion | Resaltado de vista activa | FE | RF | U | MoSCoW: M
  Descripcion: La vista seleccionada se resalta visualmente.
  Entradas   : Vista actual en el estado de la app.
  Proceso    : Aplica clase activa al item correspondiente.
  Salidas    : Item con color/fondo distinto y aria-current.
  CA-01: Dada una vista abierta, su item del sidebar es el unico resaltado.
  CA-02: Al cambiar de vista, el resaltado se mueve en menos de 100 ms.

RF-FE-03 | M1 Navegacion | Selector de proyecto | FE | RF | U | MoSCoW: M
  Descripcion: Desplegable del header que cambia el proyecto activo.
  Entradas   : Lista de proyectos disponibles; proyecto activo.
  Proceso    : Al elegir otro proyecto actualiza el contexto global.
  Salidas    : Nombre del proyecto activo y datos recalculados en las vistas.
  CA-01: Al seleccionar un proyecto, el header muestra su nombre.
  CA-02: Las vistas de analisis muestran datos del proyecto elegido.

RF-FE-04 | M1 Navegacion | Selector global de nivel | FE | RF | U | MoSCoW: M
  Descripcion: Permite elegir Basico/Intermedio/Avanzado y conservarlo.
  Entradas   : Seleccion del usuario (3 opciones).
  Proceso    : Guarda el nivel en el estado global y lo pasa al chat.
  Salidas    : Nivel activo visible y aplicado a las respuestas.
  CA-01: Al elegir "Avanzado", el chat responde con nivel avanzado.
  CA-02: El nivel se conserva al cambiar de vista.

RF-FE-05 | M1 Navegacion | Boton Subir Repo Git | FE | RF | U | MoSCoW: M
  Descripcion: Abre el modal de ingesta de proyectos desde el header.
  Entradas   : Clic del usuario.
  Proceso    : Cambia el estado del modal a visible.
  Salidas    : Modal de ingesta con sus 3 pestanas.
  CA-01: Al hacer clic, el modal aparece en menos de 300 ms.
  CA-02: El modal se cierra con la X y con la tecla Escape.

RF-FE-06 | M1 Navegacion | Indicador de cuota de tokens | FE | RF | S | MoSCoW: C
  Descripcion: Muestra el consumo de tokens en la barra lateral.
  Entradas   : Contador de tokens (simulado en v1.0).
  Proceso    : Dibuja barra de progreso y porcentaje.
  Salidas    : Indicador visible con valor numerico.
  CA-01: El indicador muestra un valor entre 0 y 100%.
  CA-02: [P] El valor se actualiza con el consumo real de la sesion.

RF-FE-07 | M1 Navegacion | Estados de carga y error | FE | RF | U | MoSCoW: M
  Descripcion: Cada vista muestra spinner al cargar y mensaje claro si falla.
  Entradas   : Estado de carga o error de la vista.
  Proceso    : Renderiza spinner (animate-spin) o bloque de error.
  Salidas    : Feedback visual y accion de reintento.
  CA-01: Mientras carga una vista se ve un spinner.
  CA-02: Ante un error se muestra el motivo y un boton de reintento.

RF-BE-01 | M1 Navegacion | Servicio de la SPA | BE | RF | S | MoSCoW: M
  Descripcion: Sirve la app con Vite middleware en desarrollo y estaticos en
    produccion, con fallback a index.html.
  Entradas   : Peticion HTTP del navegador.
  Proceso    : En dev usa Vite; en prod sirve dist/ y devuelve index.html para
    rutas del cliente.
  Salidas    : HTML/JS/CSS con HTTP 200.
  CA-01: GET / responde 200 con el HTML de la app.
  CA-02: GET /cualquier-ruta-de-vista responde el index.html (no 404).

RF-BE-02 | M1 Navegacion | Estado del sistema [P] | BE | RF | S | MoSCoW: S
  Descripcion: Endpoint GET /api/health devuelve estado del servidor y de la IA.
  Entradas   : Peticion GET sin cuerpo.
  Proceso    : Comprueba proceso, version y si aiClient esta inicializado.
  Salidas    : {status, uptime, ai: "gemini"|"fallback", version}.
  CA-01: Sin key configurada devuelve ai="fallback" y HTTP 200.
  CA-02: Con key valida devuelve ai="gemini".

  Entradas   : Texto del usuario.
  Proceso    : Valida URL no vacia y con formato http(s) o git.

RF-FE-14 | M3 Ingesta | Drag & drop de ZIP | FE | RF | U | MoSCoW: M
  Descripcion: Acepta archivos .zip con validacion de extension y tamano.
  Entradas   : Archivo arrastrado o elegido en el selector.
  Proceso    : Verifica extension .zip y tamano <= 200 MB.
  Salidas    : Archivo aceptado y nombre visible; o error claro.
  CA-01: Un .zip valido se muestra con su nombre y tamano.
  CA-02: Un .rar o .txt muestra "Solo se aceptan archivos .zip".
  CA-03: Un ZIP > 200 MB muestra error de tamano y no se procesa.

RF-FE-15 | M3 Ingesta | Progreso por 4 pasos | FE | RF | U | MoSCoW: M
  Descripcion: Animacion que muestra el avance del analisis paso a paso.
  Entradas   : Eventos del pipeline de analisis.
  Proceso    : Avanza los pasos con estado pendiente/activo/completado.
  Salidas    : Lista de 4 pasos con check o spinner.
  CA-01: Durante el analisis se ve el paso activo con spinner.
  CA-02: Al terminar, los 4 pasos quedan en completado.

RF-FE-16 | M3 Ingesta | Error con reintento | FE | RF | U | MoSCoW: M
  Descripcion: Si el analisis falla, muestra el motivo y permite reintentar.
  Entradas   : Error del pipeline o del endpoint.
  Proceso    : Detiene la animacion y muestra el mensaje.
  Salidas    : Bloque de error con boton "Reintentar".
  CA-01: Un ZIP corrupto muestra el error y no deja la UI bloqueada.
  CA-02: "Reintentar" vuelve al paso 1 y relanza el analisis.

RF-BE-06 | M3 Ingesta | Analisis de digest [P] | BE | RF | S | MoSCoW: M
  Descripcion: POST /api/analyze recibe el digest y devuelve el analisis.
  Entradas   : {name, files, totalFiles, codeFiles, totalSloc, languages,
    dependencies, entryCandidates, textSample, sourceKind}.
  Proceso    : Valida el digest, arma el prompt y consulta Gemini; si falla o
    no hay key, calcula con heuristicas.
  Salidas    : {name, description, languages, astHealth, debtHours, spofCount,
    reposCount, summary, model}.
  CA-01: Un digest valido responde 200 con astHealth entre 0 y 100.
  CA-02: Sin GEMINI_API_KEY responde 200 con model="heuristic".
  CA-03: Un body sin name o sin files responde 400.
  CA-04: El servidor no recibe el ZIP, solo el digest (<= 48 KB de muestra).

RF-BE-07 | M3 Ingesta | Analisis por URL [P] | BE | RF | S | MoSCoW: S
  Descripcion: POST /api/analyze-url descarga un repo Git o un sitio y lo
    analiza.
  Entradas   : {url, branch}.
  Proceso    : Descarga el ZIP del repo (GitHub/GitLab/Bitbucket) o los assets
    del sitio, aplica los mismos limites del digest y analiza.
  Salidas    : ProjectAnalysis o error 502 si el origen no responde.
  CA-01: Una URL de GitHub valida devuelve 200 con lenguajes y SLOC.
  CA-02: Una URL inexistente devuelve 502 con mensaje claro.
  CA-03: Una URL no permitida (esquema file://) devuelve 400.

RF-BE-08 | M3 Ingesta | Extraccion y metricas [P] | BE | RF | S | MoSCoW: M
  Descripcion: Descomprime el ZIP y calcula SLOC, lenguajes, archivos y
    dependencias.
  Entradas   : Archivo ZIP.
  Proceso    : Omite node_modules/.git/dist; lee hasta 300 archivos de texto y
    4 MB; cuenta SLOC y dependencias de package.json, requirements.txt,
    go.mod y Cargo.toml.
  Salidas    : Digest con totales y muestra de texto.
  CA-01: Un ZIP de 100 archivos devuelve totalFiles correcto.
  CA-02: node_modules no se cuenta en SLOC ni en la muestra.
  CA-03: Se extraen hasta 30 dependencias de package.json.
