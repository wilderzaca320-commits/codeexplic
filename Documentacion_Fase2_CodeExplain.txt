==============================================================================
 DOCUMENTACION - FASE 2: MAPEO DE FUNCIONALIDADES (BACKEND Y FRONTEND)
 Proyecto: CodeExplain - Analisis & Explicacion de Software con IA
 Alcance: SOLO la parte practica (inventario + requerimientos atomicos)
 Fecha: 11/11/2026
==============================================================================

Objetivo de la fase:
Convertir lo investigado en la Fase 1 en un inventario funcional separado
por capa (Frontend / Backend) y en requerimientos atomicos (una sola cosa
por requerimiento), clasificados segun el Tema 4.

LEYENDA DE CLASIFICACION
  Capa   : FE = Frontend | BE = Backend
  Tipo   : RF  = Requerimiento funcional
           RNF = Requerimiento no funcional (atributo de calidad)
           RN  = Regla de negocio
           RE  = Restriccion
  Origen : U = Requerimiento de usuario
           S = Requerimiento de sistema
  [P]    : Propuesto (aun no implementado). Sin marca = implementado hoy.


==============================================================================
 1. INVENTARIO FUNCIONAL POR MODULO (15 modulos)
==============================================================================

M1. NAVEGACION / SHELL
  Frontend: sidebar con 12 vistas en 3 bloques; resaltado de vista activa;
            selector de proyecto en el header; selector global de nivel
            (Basico/Intermedio/Avanzado); boton "Subir Repo Git"; indicador
            de cuota de tokens; spinners y mensajes de error por vista.
  Backend : servicio de la SPA (Vite middleware en dev, estaticos en prod);
            fallback a index.html para rutas del cliente.

M2. PROYECTOS (WORKSPACE)
  Frontend: tarjetas con tag, lenguajes, salud AST, deuda, SPOF y actividad;
            seleccion de proyecto activo; boton "Nuevo proyecto"; navegacion
            a vistas de analisis del proyecto.
  Backend : persistencia de proyectos; lista y alta de proyectos.

M3. INGESTA DE REPOSITORIOS (MODAL)
  Frontend: modal con 3 pestanas (Git remoto, ZIP/Carpeta, Pegar codigo);
            formulario Git (URL, rama, motor de parser); zona drag & drop de
            ZIP con validacion de extension y tamano; animacion de 4 pasos;
            mensaje de error con reintento.
  Backend : recepcion del digest del proyecto; descarga de repos Git o sitios
            web; extraccion de ZIP y calculo de metricas (SLOC, lenguajes,
            dependencias).

M4. CHAT IA (3 NIVELES)
  Frontend: burbujas de conversacion (avatar, hora, nivel); entrada con boton
            y Enter; pills de nivel; copiar respuesta; scroll automatico;
            bienvenida contextual; prompts precargados desde otras vistas;
            renderizado Markdown de respuestas.
  Backend : endpoint de chat con contexto del proyecto; prompts por nivel;
            fallback heuristico sin API key; memoria multi-turno; limites de
            latencia.

M5. VISION GENERAL
  Frontend: dashboard con metricas clave y accesos rapidos; preguntas
            sugeridas que abren el chat.
  Backend : endpoint de metricas del proyecto.

M6. ARQUITECTURA & MODULOS
  Frontend: vista de modulos con dependencias y acoplamiento; seleccion de
            modulo con detalle.
  Backend : calculo de acoplamiento por modulo (Ca, Ce, inestabilidad).

M7. DIAGRAMAS C4 & UML
  Frontend: diagrama C4 interactivo con nodos y flujos animados; seleccion
            de nodo con panel de detalle.
  Backend : generacion de diagramas C4/PlantUML desde el AST.

M8. MODELO DE DATOS / BD
  Frontend: vista de tablas con PK/FK/unique y particionamiento; busqueda y
            filtro de tablas y columnas.
  Backend : introspeccion del esquema de base de datos del proyecto.

M9. CASOS DE USO & REQUERIMIENTOS
  Frontend: vista de casos de uso (actor, pre/postcondicion, complejidad,
            pasos); visualizacion del escenario Gherkin.
  Backend : extraccion de casos de uso desde rutas y controladores.

M10. RIESGOS & VALIDACION
  Frontend: vista de riesgos STRIDE con severidad, estado, impacto y
            mitigacion.
  Backend : analisis de dependencias vulnerables (CVE).

M11. AUDITOR DE DEUDA TECNICA
  Frontend: vista de deuda con horas estimadas y dependencias obsoletas;
            exportacion del informe.
  Backend : calculo de deuda tecnica a partir de metricas del codigo.

M12. GENERADOR DE DOCUMENTACION
  Frontend: selector de tipo (README, OpenAPI, C4, ADR); vista previa;
            copiar; descargar archivo.
  Backend : endpoint de generacion de documentos; generacion real con Gemini
            y fallback por plantilla.

M13. HISTORIAL DE CONSULTAS
  Frontend: vista de historial (categoria, repo, tokens, pregunta, resumen);
            marcar favorito; reenviar consulta al chat.
  Backend : persistencia de consultas y endpoint de historial.

M14. REPOSITORIOS ANALIZADOS
  Frontend: vista de repos (rama, lenguaje, SLOC, estado AST, ultimo commit);
            accion de re-analizar/sincronizar.
  Backend : endpoint de estado de sincronizacion de repos.

M15. CONFIGURACION / IA / SEGURIDAD
  Frontend: (sin pantallas propias; consume el estado del servidor).
  Backend : carga de GEMINI_API_KEY desde entorno; inicializacion segura del
            cliente IA; proteccion de la key; limites de payload; manejo de
            errores JSON; motor de respaldo; filtro de archivos binarios.

==============================================================================
 4. REGLAS DE NEGOCIO Y RESTRICCIONES (detalle)
==============================================================================

RN-01 (Documentacion) : Todo documento generado debe describir al proyecto
                        activo; no se aceptan plantillas de otro proyecto.
RN-02 (IA)            : Si no hay GEMINI_API_KEY o la API falla, el sistema
                        responde con el motor heuristico local; la sesion
                        nunca se interrumpe.
RN-03 (Ingesta)       : Solo se analizan archivos de texto/codigo; los
                        binarios (imagenes, videos, fuentes) se omiten del
                        contenido y solo se cuentan como archivos.
RN-04 (Privacidad)    : Antes de enviar codigo o preguntas a Gemini, la
                        interfaz debe avisar al usuario.

RE-01 (Entorno)       : Node.js 20+ y navegador con soporte ES2022.
RE-02 (Entorno)       : Puerto configurable por variable PORT; por defecto
                        3000 y en este equipo 3100 (3000 reservado).
RE-03 (Entorno)       : La ruta del proyecto no debe contener caracteres
                        especiales (a con tilde, &, etc.) por compatibilidad
                        de npm en Windows.
