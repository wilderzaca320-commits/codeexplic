1.3 PRINCIPIOS
  UX
  U1. Evidencia antes que simulacion: nada se muestra como dato real si es mock.
  U2. Una tarea, un camino: cada objetivo tiene una ruta principal y una salida.
  U3. Progreso visible: toda operacion larga muestra que hace y cuanto falta.
  U4. Accesible por defecto: teclado, foco, contraste y lector de pantalla.
  U5. El error explica y ofrece la salida, no solo "algo fallo".
  U6. El conocimiento se cita: toda afirmacion enlaza a su evidencia (F5).
  DX
  D1. Un comando para levantar el entorno, cero pasos manuales.
  D2. El error aparece en < 10 min y en el mismo PR que lo causa.
  D3. El contrato de API es la fuente de verdad y genera tipos.
  D4. Las decisiones se documentan donde se leen (ADR + README).
  D5. Lo repetitivo se automatiza: formato, lint, dependencias, releases.

2.2 USER PERSONAS

P1. ANA - DESARROLLADORA JUNIOR (aprende leyendo codigo ajeno)
  Perfil : 23 anos, 1 ano de experiencia, frontend React. Entra a un proyecto
           heredado y necesita entenderlo sin molestar al equipo.
  Objetivo: saber que hace el sistema, por donde empieza y que puede romper.
  Contexto: 30-60 min disponibles, muchas pestanas abiertas, poca paciencia.
  Nivel de conocimiento del dominio: bajo.
  Frase  : "Necesito que alguien me explique este repo como si tuviera 20
           minutos, no un manual de 200 paginas."

P2. MARCO - TECH LEAD / ARQUITECTO (audita antes de un release)
  Perfil : 38 anos, 12 de experiencia, responsable de 4 equipos.
  Objetivo: decidir si el release es seguro; priorizar deuda y riesgos.
  Contexto: reuniones, revisiones, necesita datos defendibles y exportables.
  Nivel: alto.
  Frase  : "No quiero una opinion; quiero ver el riesgo, su evidencia y
           cuanto cuesta arreglarlo."

P3. LUCIA - DOCENTE / CONSULTORA (explica y documenta para terceros)
  Perfil : 45 anos, dicta cursos y asesora equipos.
  Objetivo: producir material comprensible en 3 niveles y reutilizarlo.
  Contexto: prepara clases y entregables; valora exportar y citar.
  Nivel: medio-alto.
  Frase  : "Si no puedo mostrar de donde sale cada afirmacion, no lo uso
           en clase."

3.2 MODELO DE NAVEGACION
  Nivel 0  Shell: sidebar + header + area de contenido.
  Nivel 1  Grupo del sidebar (Explorar / Analisis / Herramientas IA).
  Nivel 2  Vista (12).
  Nivel 3  Detalle en panel o modal (modulo, tabla, riesgo, documento).
  Transversal: selector de proyecto, busqueda global, ayuda, subir.

  Breadcrumb: Proyecto > Grupo > Vista > Detalle.
  En movil (< 960px): sidebar colapsado en drawer; breadcrumb a "Vista > Detalle".

3.3 USER FLOWS

F-01 ANALIZAR UN PROYECTO (camino principal)
  1. Usuario pulsa "Subir proyecto" (header o vista Proyectos).
  2. Modal W-2: elige pestana ZIP o URL.
  3. Sistema valida tamano y extension; muestra error inline si falla.
  4. Pulsa "Analizar". Se abre progreso con 5 fases:
     Inventario -> Dependencias -> Modulos -> Metricas -> Hallazgos.
  5. Cada fase muestra estado (pendiente / en curso / hecho / error) y
     permite cancelar.
  6. Al terminar: toast "Analisis listo" + CTA "Ver vision general".
  7. Vision general muestra metricas, semaforo de riesgo y "siguiente paso".
  8. Si una fase falla: se conserva lo calculado, se explica el motivo y se
     ofrece reintentar solo esa fase.

F-02 CONSULTAR A LA IA
  1. Usuario abre Chat (sidebar o CTA contextual desde cualquier vista).
  2. El contexto de la vista activa se adjunta como referencia (modulo, riesgo).
  3. Elige nivel: Basico / Intermedio / Avanzado (recordado por sesion).
  4. Escribe o elige una pregunta sugerida.
  5. Respuesta en streaming con Markdown seguro y citas [KU-xxxxx].
  6. Puede copiar, guardar en historial o convertir en documento.
  7. Si Gemini no esta disponible: aviso claro "modo heuristico" y respuesta
     local; nunca se muestra como si fuera IA.

F-03 GENERAR DOCUMENTACION
  1. Abre Generador de Documentacion.
  2. Selecciona tipo: README, OpenAPI, C4, ADR.
  3. Ve vista previa por secciones y que KUs la componen.
  4. Genera: estado por seccion (ok / sin informacion).
  5. Descarga .md / .puml / .json o copia; se registra version y checksum.
  6. Puede volver al analisis desde cada seccion citada.

3.4 REGLAS DE INTERACCION
  IA-4. Toda vista tiene titulo, subtitulo de una linea y accion primaria.
  IA-5. Toda vista tiene estado vacio con una accion (no solo texto).
  IA-6. Toda vista tiene estado de carga (skeleton) y de error (reintentar).
  IA-7. Las acciones destructivas piden confirmacion y se pueden deshacer.
  IA-8. El proyecto activo se muestra siempre en el header.
  IA-9. Navegacion por teclado: Ctrl/Cmd+K buscador, G+P/A/C ir a,
        Esc cerrar, ? ayuda. [P]

3.5 BUSQUEDA GLOBAL [P]
  - Abre overlay con Ctrl/Cmd+K.
  - Busca en: vistas, proyectos, modulos, tablas, riesgos, documentos, KUs.
  - Resultados agrupados por tipo con su breadcrumb.
  - Enter abre; flechas navegan; Esc cierra.
  - Sin resultados: sugiere quitar filtros y ofrece el glosario.

4.7 ESPECIFICACIONES DE INTERACCION
  W-1: sidebar colapsable (240px -> 64px); estado activo con barra neon y
       aria-current="page"; tooltip en modo colapsado.
  W-2: drag & drop con feedback; validacion antes de enviar; foco atrapado;
       Esc cierra; al cerrar con analisis en curso, confirmar.
  W-3: metricas clicables que llevan a su vista; "siguiente paso" derivado de
       los hallazgos, no generico.
  W-4: autoscroll solo si el usuario esta al final; streaming cancelable;
       citas clicables que abren la ficha de la KU.

  ----------------------------------------------------------------
  FROM node:22-alpine AS deps
  WORKDIR /app
  COPY package*.json ./
  RUN npm ci

  FROM node:22-alpine AS build
  WORKDIR /app
  COPY --from=deps /app/node_modules ./node_modules
  COPY . .
  RUN npm run build && npx esbuild server.ts --bundle \
      --platform=node --format=esm --outfile=dist/server.js

  FROM node:22-alpine AS runtime
  WORKDIR /app
  ENV NODE_ENV=production
  COPY package*.json ./
  RUN npm ci --omit=dev
  COPY --from=build /app/dist ./dist
  EXPOSE 3100
  HEALTHCHECK CMD wget -qO- http://localhost:3100/api/health || exit 1
  CMD ["node","dist/server.js"]
  ----------------------------------------------------------------

  ----------------------------------------------------------------
  services:

        test: ["CMD","wget","-qO-","http://localhost:3100/api/health"]

8.6 CI/CD
  Pipeline de PR (.github/workflows/ci.yml) [P]:
    jobs:
      quality: checkout -> setup-node 22 (cache npm) -> npm ci ->
               npm run typecheck -> npm run lint -> npm test -- --run ->
               npm run build -> subir artefacto
      e2e (opcional): levantar contenedor y correr Playwright en 3 flujos
      preview: construir imagen y publicar preview por PR
  Optimizaciones: cache de npm, cache de Vite, jobs en paralelo, matriz
  Node 20/22 solo en main, timeout 10 min.
  Preview environments: como C-TEC-01 exige un solo equipo y C-BIZ-01 coste
  cero, el preview corre en el mismo servidor Windows con un puerto por PR
  (3200 + numero de PR % 500) y un tunel; se destruye al cerrar el PR.
  Alternativa cloud si se aprueba: Render/Fly con free tier.
  Proteccion de main: CI obligatoria, 1 review, rama actualizada, sin
  force-push. Releases: tag + changelog + imagen en ghcr.io.
  Objetivo: feedback < 10 min (p95), pipeline < 5 min.

8.7 REDUCCION DE CARGA COGNITIVA
  - ESLint flat config con typescript-eslint, react-hooks y jsx-a11y.
  - Prettier unico (printWidth 100, singleQuote, trailingComma all).
  - husky + lint-staged: formato y lint solo en archivos cambiados.
  - EditorConfig y .nvmrc (22) para paridad de entorno.
  - Dependabot semanal agrupado (prod/dev), auto-merge de parches con CI.
  - Logs con pino: nivel, requestId, ruta, duracion, resultado; en dev
    pino-pretty; nunca loguear la API key ni el contenido del codigo.
  - Errores: ErrorBoundary por vista + toast con accion "reintentar".
  - Convenciones: nombres de archivo y de componente iguales; un componente
    por archivo; imports absolutos con alias @/.
  - Documentacion viva: ADR en /docs/adr, decisiones en el PR.
  - Onboarding: `npm run doctor` + tour de 10 min en el README.
